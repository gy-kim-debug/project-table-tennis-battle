# Phase 1 상세 작업 계획

현재 1~7,9의 구현 및 자동 검증을 수행했다. 8의 사용자 직접 플레이 검수는 남아 있다. 구현 시작 시 AGENTS.md, GAME_DESIGN.md, Git 상태를 다시 확인한다.

1. Godot 4.6.3으로 project.godot와 최소 Battle 씬 생성. 360×640 검토 해상도, 세로 방향, Nearest 설정. HP/전투/AI/압박 코드는 추가하지 않는다.
2. 후방 대각선 20도 고정 구도에 맞는 임시 사다리꼴 탁구대·네트·고정 플레이어/상대를 도형으로 배치. 목표 타격 위치, 깊이 축, 상하 UI 영역을 문서화한다. 20도 구도는 사용자 시각 검수가 필요하다.
3. 기본 리턴 한 종류의 PatternData와 시간 기반 궤적/바운드/그림자를 구현. 모든 공은 고정 타격 위치 도착. 다른 4패턴은 Phase 3.
4. 독립 TimingJudge와 게임 시계 구현. ±50/120/180ms 초기값을 데이터로 관리. 프레임 수 대신 입력 기록 시각 사용. 입력 없는 자동 Miss, 조기 스윙 소모, 공당 한 번, 중복 터치 차단.
5. 터치/디버그 클릭/Space 입력을 같은 스윙 경로로 연결. 판정 텍스트와 임시 스윙 반응 표시. 스윙 중 추가 입력 무시.
6. 최소 랠리: AI에서 발사 → 플레이어 타이밍 → 성공 리턴 → 상대 자동 리턴. AI 수비 확률 없이 연속성 검증. Miss는 랠리 종료 후 재시작. HP/승패는 Phase 2.
7. 자동 검증: 판정의 양쪽 경계/직전/직후, 조기/늦은/무입력, 연타/합성 클릭, 30/60/120fps, 반복 루프 최소 10회, Miss 재시작. 엔진 import/parse 오류 확인.
8. 수동 검증: 임시 그래픽으로 실제 최소 10회 연속 랠리. 공 가독성/바운드/타격 순간/구도 확인. 자동 시뮬레이션 통과만으로 수동 완료를 표시하지 않는다.
9. GAME_DESIGN/ARCHITECTURE/ROADMAP에 실제 구현/실행 결과와 결정값 기록. README에 엔진 열기 및 테스트 명령 추가.

## 완료 조건
실행 가능한 Godot 씬에서 원버튼으로 공을 받아치며 수동 최소 10회 연속 랠리 가능. 타이밍 경계와 중복 입력 자동 검증 통과. 문서와 구현 일치. 실기기 체감은 별도 미검증 항목으로 남길 수 있다.

## 범위 밖
HP 피해, AI 수비 공식, 압박, 난이도, 패턴 확장, 최종 아트, 완성 사운드/히트 스톱, iOS 서명/배포. 기획 변경이 필요한 경우 변경 이유/대안/영향을 제시하고 사용자 결정 후 반영한다.
