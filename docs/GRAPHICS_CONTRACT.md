# 그래픽 제작·교체 계약 v1

새 선수, 탁구대, 공, 배경을 만들기 **전에** 이 계약을 기준으로 제작한다. 플레이 규칙과 그래픽은 분리되어 있으므로 그래픽을 교체해도 판정 시각·HP·AI가 바뀌지 않아야 한다. 현재 값은 프로토타입 화면에서 검증한 기준이며, iPhone에서 크기와 가독성을 확인한 뒤 화면 배율만 조정할 수 있다.

## 1. 공통 화면 좌표

- 고정 시점: 플레이어 등 뒤에서 약간 높은 2D 화면. 내부 캔버스 360×640, 세로 9:16, Nearest. 카메라 이동은 없다.
- 탁구대 좌표: `x=-1` 왼쪽 가장자리, `x=1` 오른쪽 가장자리, `depth=0` 상대 쪽 먼 가장자리, `depth=1` 플레이어 쪽 가까운 가장자리. `height`는 화면에서 위로 올릴 픽셀 수다.
- 투영의 **단일 기준값**은 [`assets/table/layout.json`](../assets/table/layout.json)이다. 실제 공·그림자·접촉점은 `CourtView.project_point()`로 투영하고, 탁구대·네트 PNG는 `tools/assets/build_court.py`가 같은 값으로 생성한다. 원근을 바꿀 때 둘을 함께 재생성·검사한다.
- 양쪽 라켓의 논리 접촉점은 패턴 Resource의 `start_point`/`hit_point`다. 미술 작업에서 타격점을 옮겨 타이밍을 맞추지 않는다. 모든 패턴의 목표점은 동일한 플레이어 위치로 수렴한다.

## 2. 화면 가림 순서

뒤에서 앞으로: **배경 → 상대 전신 → 탁구대 본체/상판 → 먼 쪽 공 → 네트 → 플레이어 전신 → 가까운 쪽 공 → 타격·피격 효과 → UI**. 탁구대의 불투명 상판이 상대 하반신을 실제 원근 경계에서 가린다. 2026-10-14에 이전의 고정 `y=208` 상대 잘라내기를 제거했다. 화면 Y좌표에 맞춘 임의의 캐릭터 잘라내기를 새로 추가하지 않는다.

이 순서는 현재 상대가 **탁구대 뒤에 서는** 구도에 맞다. 앞으로 상대의 손/라켓이 탁구대 앞까지 뻗는 그림을 원한다면, 그 포즈는 `body_back`과 `arm_front`처럼 깊이 레이어를 나눈 별도 에셋이 필요하다. 지금의 단일 PNG 시트를 탁구대 위에 통째로 올리면 다시 몸이 상판을 뚫고 보인다. 배경·상판·네트·캐릭터를 하나의 완성 화면 PNG로 합치지 않는다.

## 3. 교체 가능한 에셋 단위

| 종류 | 현재 계약 | 교체 시 지켜야 할 점 |
|---|---|---|
| 플레이어/상대 | 역할별 128×128 투명 프레임; Idle 4, Swing 6, Miss 4; SpriteFrames와 `manifest.json` | 같은 역할·시점, 동일 발 pivot과 라켓 접촉점, 프레임 간 발 위치. 새 캐릭터는 별도 폴더에 같은 구조를 두고 `layout.json`의 `player_character` 또는 `enemy_character` ID를 바꾼다. |
| 탁구대 | 360×640 투명 `table_main.png` | 상판의 먼/가까운 경계가 `layout.json` 투영과 일치해야 한다. 상대를 가릴 부분은 불투명하게 유지한다. |
| 네트 | 360×640 투명 `table_net.png` | `net_depth`와 양쪽 포스트 위치를 일치시킨다. 먼 공 뒤/가까운 공 앞의 기준이다. |
| 공·그림자 | 중심 pivot의 12×12/16×6 투명 PNG | 공의 중심은 궤적 좌표에, 그림자는 같은 x/depth의 지면 좌표에 둔다. 강한 공 색상 변형에도 실루엣이 읽혀야 한다. |
| 배경 | 360×640 불투명 PNG | 선수/공보다 낮은 대비, 주요 UI와 접촉점 주변은 단순하게 유지한다. |
| UI·효과 | 별도 CanvasLayer/표시 효과 | 게임 규칙을 직접 변경하지 않고 전투 이벤트만 받아 표시한다. |

**128×128은 캐릭터의 원본 셀 크기이지 게임에서 보이는 크기가 아니다.** 현재 `player_scale=3`, `enemy_scale=1.55`라 상대의 1픽셀은 화면에서 균일한 정수 픽셀이 아니다. 이는 프로토타입의 구도 조정값이며, 최종 캐릭터를 대량 제작하기 전 iPhone 화면에서 도트 선명도와 상대 크기를 검토해야 한다. 필요하면 더 적합한 원본 크기/정수 배율로 에셋 전체를 함께 바꾼다. 개별 캐릭터마다 임의로 스케일을 달리해 접촉점을 맞추지 않는다.

## 4. 새 그래픽 투입 절차

1. 같은 역할의 기존 에셋을 복사해 **한 종류만** 교체한다. 새 캐릭터 폴더에서는 `frames.tres`의 PNG 경로도 새 파일로 갱신한다. 원본 생성 파일과 게임용 PNG를 구분하고, ID·크기·프레임 수·pivot·라켓 접촉점·알파 여부를 `manifest.json` 또는 제작 기록에 남긴다.
2. 이미지의 머리/발/라켓 끝이 셀 경계에 잘리지 않는지, 프레임 사이 기준점이 흔들리지 않는지 확인한다. 배경과 탁구대는 레이어 분리와 원근 경계를 확인한다.
3. Godot import 후 `tests/run_tests.gd`, `tests/character_render_smoke.gd`, `tests/phase3_render_smoke.gd`로 5패턴×3난이도·Idle/Swing/Miss·탁구대 가림·접촉을 확인한다. 정면/후면 시점이 섞이거나 네트 앞뒤가 뒤집히면 통합하지 않는다.
4. 실제 iPhone에서 구도·도트 밀도·글자·공 대비를 확인한다. 이 단계는 아직 미검증이며 사용자가 나중에 실행해 피드백할 예정이다.

## 5. 현재 뼈대와 확장 시점

이미 있는 뼈대는 `layout.json`(투영·캐릭터 슬롯), 패턴 Resource(논리 궤적/타격점), 캐릭터 `manifest.json`+`frames.tres`(프레임/기준점), 분리된 배경·탁구대·네트·공 PNG, BattleUI(CanvasLayer)다. 이번에는 화면 가림 순서와 검증을 바로잡았다.

아직 **캐릭터 선택/스킨 카탈로그, 앞·뒤로 나뉜 팔 애니메이션, 최종 UI/폰트**는 없다. 새 그래픽 종류를 대량으로 만들기 전에 어떤 변형이 필요한지 정하고, 그 변형이 현재 계약에서 교체만으로 가능한지 확인한다. 여러 선수나 테이블 테마를 실제 게임에서 선택하도록 만들 때는 역할/ID를 선언하는 카탈로그를 추가한다. 현재 두 역할만을 위해 추상적인 범용 에셋 시스템을 먼저 만들 필요는 없다.
